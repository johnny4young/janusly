# Agent Notes — Janusly

Operational invariants only — how to run the project, what not to break. Roadmap and ticket pool live in [`docs/ROADMAP.md`](docs/ROADMAP.md). Strategic context lives in [`docs/PLAN.md`](docs/PLAN.md). Don't add planning here.

Janusly = the AI operator for business workflows. Internal packages live under the `@janusly/*` scope. Everywhere user-facing (UI brand-mark, page titles, marketing copy, `/ai/*` responses) say **Janusly**.

- **Stack baselines:** Node.js **24**, TypeScript 6, React 19, Vite 8 (Rolldown), Tailwind 4 (CSS-first via `@theme` + `@tailwindcss/vite`), Vitest 4, Zod 4, Drizzle 0.45, Postgres 18, Redis 8, OpenAI SDK 6.
- **Design system:** Workflow palette (Cobalt `#245BFF` + Cyan `#06B6D4` + green/amber/red status). Tokens in `apps/web/src/index.css` (`@theme { --color-we-* }` + `:root` aliases). No inline hex.
- **Tailwind 4 is CSS-first.** No `tailwind.config.ts` or `postcss.config.js`. The plugin runs through `@tailwindcss/vite()` in `apps/web/vite.config.ts`.
- **Vite 8 / Rolldown:** `build.rollupOptions.output.manualChunks` must be a function, not an object literal.
- **Zod 4:** `z.record(z.string(), z.unknown())` — two-arg form.
- **Auth:** dev-mode uses `x-org-id` and `x-user-id` headers, allowed automatically when Supabase is unset **and** `NODE_ENV !== "production"`. Production without Supabase requires explicit `ALLOW_DEV_AUTH_HEADERS=true` or the API refuses to start. The `dev-headers` mode falls back to the `admin` role only when no `org_members` row exists; `service-token` mode does **not** auto-grant admin.
- **HTTP/SSRF:** `ALLOW_PRIVATE_HTTP_TARGETS=false` blocks localhost/private/link-local for `http` nodes and the `http.request` tool. The validated DNS resolution is pinned for the actual TCP connect via an `undici.Agent` `connect.lookup` hook, so DNS rebinding (public IP at validation, private IP at connect time — e.g. `169.254.169.254` AWS metadata) cannot redirect the connect to a private target. Don't unwind the pinned dispatcher path in `packages/engine/src/http-policy.ts`.
- **Rate limiter:** API rate-limit state lives in Redis (`apps/api/src/redis.ts` + `apps/api/src/rate-limit.ts`) so counts are shared across all API replicas. Backed by `INCR` + `PEXPIRE` with a `janusly:rate:<name>:<orgId>` key. Fails **open** with a `[rate-limit]` warn log when Redis is unreachable — never fail closed; an AI Studio outage during a Redis blip is worse UX than a brief over-limit window. Don't reintroduce the in-memory `Map` fallback.
- **Usage events:** every LLM call writes one row to `usage_events` from the chokepoint `LlmClient.generateText` (ENG-012). The recorder is registered process-globally via `setUsageRecorder(recordUsage)` at api + worker boot; `packages/ai` itself stays DB-agnostic. `metric: "llm.completion"`, `quantity: totalTokens`, `metadata: { provider, model, inputTokens, outputTokens, latencyMs, costUsd, nodeId, mode, aiError }`. Cost is computed from `packages/ai/src/pricing.ts` (defaults + `JANUSLY_LLM_PRICE_<MODEL>` env override); unknown models record `costUsd: null`. Recorder failures are caught and dropped — telemetry must never break an LLM call. Don't bypass the chokepoint by calling `aiGenerateText` directly from outside `packages/ai`. Engine-side `orgId` plumbs through `NodeContext.orgId`, populated once per node execution by `executeNode` via `getRunOrgId(runId)`.
- **AI integration:** every AI surface (`/ai/generate-workflow`, `/ai/explain-workflow`, `/ai/explain-run`, the `agent` planner `"openai"`, the `ai` step type) routes through the provider-neutral `getLlmClient()` in `packages/ai/src/llm-client.ts` (built on the Vercel AI SDK). `JANUSLY_LLM_PROVIDER` (default `openai`; today `openai` + `anthropic` registered) plus the matching `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` selects the backend at deploy time. Per-call overrides go through the `model` field on workflow nodes / API request bodies: a bare id (`"gpt-4o-mini"`) uses the configured provider; `"<provider>/<model>"` (e.g. `"anthropic/claude-haiku-4-5"`) overrides provider for that one call. Adding a new provider (Ollama, Mistral, Google) is a four-field entry in the `PROVIDERS` registry — no other code changes; see `packages/ai/README.md`. Every AI path has a deterministic fallback **and** wraps the SDK invocation in try/catch — on any failure (quota, rate, network, bad output, unknown provider, missing key for an override) the response stays `{ mode: "fallback", aiError: "<reason>", ... }` with the local content attached. Never break the fallback or remove the try/catch. `GET /ai/health` reports `enabled`, `provider`, and `model` reflecting whichever backend is currently active. `parseAiWorkflow` (in `apps/api/src/index.ts`) has a **loosener** that coerces wrong-typed ids and drops invalid edge/condition expressions before Zod parses; keep it when adding fields so the LLM's near-misses still validate (ENG-014 will replace it with `generateObject({ schema: WorkflowSchema })`).
- **Decision engine / RL:** `packages/domain` is pure logic, no I/O. `packages/data` owns the drizzle repos. Don't put DB queries in `domain`; don't put scoring logic in `data`.
- **Tool registry:** entries in `packages/engine/src/tool-registry.ts` are typed `ToolDefinition`s with required `inputSchema` + `outputSchema` (Zod 4). `validateToolInput` and `executeTool` route inputs through `safeParse`; outputs are validated before return so executor drift surfaces immediately. Adding a new tool without both schemas is a TS error at registration. The public `listTools()` JSON shape (`name`, `description`, `required`, `optional`, `inputExample`) is part of the AI Studio contract — `required`/`optional` are derived from the input schema; don't drift the field names.
- **MCP server:** `packages/mcp-server` exposes a stdio MCP server with five read-only tools (`workflows.list`, `workflows.get`, `recipes.list`, `tools.list`, `runs.get`). Boot via `pnpm --filter @janusly/mcp-server start` (or `dev` for tsx watch). The server is a thin proxy over the existing HTTP API — no DB access, no audit writes of its own. Auth via `JANUSLY_API_SERVICE_TOKEN` (production) or dev headers (`JANUSLY_API_ORG_ID` / `JANUSLY_API_USER_ID`); the API enforces org scope. Don't add write/destructive tools without a follow-up ticket — the read-only constraint is what makes the MCP surface safe to expose by default. MCP descriptors use JSON Schema (the protocol's native shape) — distinct from the engine's Zod-backed tool registry.
- **Maintainer docs convention:** new maintainer-facing docs in `packages/*` and `apps/*` use a file-header block comment (one-line purpose, "Used by:" cross-references, invariants worth knowing) and per-export JSDoc on classes/functions/types/constants. Tone matches AGENTS.md — practical, not narrative. Keep rollout/progress tracking in `docs/ROADMAP.md`, not here.
- **Causal reasoning:** runs without an LLM. Always available.
- **Cross-panel reactivity:** when an action invalidates server data (save, run start, terminal run, member invite/remove, DLQ replay), call `bumpPlatformVersion()` on the Zustand store. Independent panels listen to it as an effect dep.
- **DLQ:** every failed node beyond `retryPolicy.maxAttempts` lands in `dead_letters`. Replay via `POST /dlq/replay`. The Operations card in Runs surfaces counts and filters. `BullMQQueueAdapter` composes `DeadLetterQueueAdapter` so DLQ insertion is part of the queue contract — don't bypass it.
- **Concurrency:** `enqueueReadyNodes` claims downstream nodes via `tryClaimNodeForQueue` (atomic `UPDATE … WHERE status='pending'`). With multiple workers two predecessors can complete simultaneously; only one wins the claim, so don't reintroduce a non-atomic `markNodeQueued` here.
- **Run setup:** `startRun` wraps the `runs` insert + batch `runNodes` insert + `run.started` event in one Drizzle transaction. Don't split it back into per-node inserts.
- **Worker lifecycle:** `worker.ts` listens to `SIGTERM`/`SIGINT` and calls `worker.close()` to drain in-flight jobs. Container restarts don't orphan `running` nodes.
- **Pagination:** `GET /runs` and `GET /workflows` cap at 100 rows by default (max 200 via `?limit=`). `GET /run` and `GET /status` cap nested `events` at 200 by default (max 500 via `?eventsLimit=`) and emit `eventsCursor` / `eventsHasMore`; older history loads via `GET /run?runId=<id>&eventsCursor=<iso>|<eventId>` (URL-encoded by clients). Don't return unbounded lists, and don't reintroduce a full-event-list fetch on the runs view.
- **Observability:** OTel tracer/meter Resource carries `service.name="janusly"`, `service.namespace="janusly"`, and `service.instance.id` (resolved via `OTEL_SERVICE_INSTANCE_ID` env, falling back to `HOSTNAME`, then `os.hostname()`). Set in `packages/engine/src/observability/resource.ts` and threaded into both the `NodeTracerProvider` (`otel.ts`) and the `MeterProvider` (`prometheus.ts`). External dashboards filtering on the legacy `workflow-engine` name need updating; multi-instance dashboards now disambiguate per-process via `service.instance.id`.
- **AI audit:** `/ai/generate-workflow` and `/ai/explain-workflow` write `audit_logs` rows on AI-mode success (`ai.workflow.generated` / `ai.workflow.explained`). Keep the audit when adding new AI endpoints.
- **Web deps:** `apps/web` only imports `react`, `react-dom`, `@xyflow/react`, `@supabase/supabase-js`, `zustand`, and `lucide-react`. No `@radix-ui`, `class-variance-authority`, `clsx`, or `tailwind-merge` — the design system is hand-written CSS in `index.css`. Don't reintroduce shadcn-style scaffolding.
- **Migrations:** schema lives in `packages/db/src/schema.ts`; checked-in SQL under `packages/db/migrations/` is generated via `pnpm --filter @janusly/db db:generate`. Apply with `pnpm migrate` (delegates to `drizzle-kit migrate`) before booting the API or worker — both call `assertMigrationsApplied()` at startup and fail fast if the `drizzle.__drizzle_migrations` table is missing. Don't reintroduce a runtime `CREATE TABLE` bootstrap. The e2e harness runs `pnpm migrate` between Compose-up and API boot.
- **Tests:** `pnpm test` runs Vitest 4 in shared, engine, ai, domain, db, api, and web (jsdom + Testing Library; `*.browser.test.tsx` files are excluded from this run by the jsdom config and execute separately via the browser-mode pool). `pnpm test:browser` runs Vitest browser mode against `apps/web/src/**/*.browser.test.tsx` via `@vitest/browser` + the existing Playwright/Chromium binary (run `pnpm --filter @janusly/web exec playwright install chromium` once on a fresh checkout). `pnpm test:e2e` boots Postgres/Redis via Compose, runs `pnpm migrate`, starts API + worker, lets Playwright bring up the UI, shuts Compose down on exit. `pnpm evals` runs `scripts/run-evals.mjs` against a running API (assumes `pnpm dev` is up; override the URL via `JANUSLY_EVALS_API_URL`); reads `evals/generate-workflow.jsonl`, POSTs each prompt to `/ai/generate-workflow`, asserts node-type shape, and exits 0 if no cases failed and 1 otherwise. Cases marked `requiresMode: "ai"` are skipped only when the API returns fallback without `aiError`, so devs without an `OPENAI_API_KEY` still see a green run while live-AI degradation remains a failure.
- **CI:** `.github/workflows/ci.yml` runs four parallel jobs on PR + push to `main` — `build_test` (`pnpm build` + `pnpm test`), `test_browser` (`pnpm test:browser` with Playwright/Chromium cached at `~/.cache/ms-playwright`), `test_e2e` (`pnpm test:e2e`, full Compose lifecycle), and `dep_audit` (`pnpm audit --audit-level high`, fails the build only on high+ advisories — keep moderate fixes in their own tickets like ENG-016). All jobs pin `pnpm@10.23.0` and `node@24` to match the root `packageManager` and `engines.node`. Don't add Compose orchestration to the workflow YAML directly — `scripts/run-e2e.mjs` already owns that lifecycle and CI must reuse it so local and CI behaviour stay identical.
- **Compose lifecycle:** if a task started Compose, run `docker compose down` before finishing unless told otherwise. The dev orchestrator at `scripts/run-dev.mjs` (invoked by `pnpm dev`) brings Compose up, runs `pnpm migrate`, spawns api/worker/web, and tears Compose down on `Ctrl+C` or any child crash. Don't reintroduce a `pnpm -r dev` fan-out at the root — it skips the Compose + migrate steps and silently breaks fresh checkouts.
- **Don't reintroduce** the deleted tRPC stub or Stripe SDK; the API is plain HTTP, billing schema columns are placeholders.
