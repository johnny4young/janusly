# Agent Notes — Janusly

Operational invariants only — how to run the project and what not to break. Keep planning/status notes out of source comments and release-facing docs.

Janusly = the AI operator for business workflows. Internal packages are scoped `@janusly/*`. Everywhere user-facing (UI brand-mark, page titles, marketing copy, `/ai/*` responses) say **Janusly**.

## Feature architecture — deep-dives

Heavy feature areas live in `docs/architecture/*.md`, kept out of this file to keep per-session context small. **Read the relevant doc before changing that area** — the full invariants (routes, tables, audit actions, env vars, "don't break" rules) live there verbatim.

- **Auth & identity** → [`docs/architecture/auth-and-identity.md`](docs/architecture/auth-and-identity.md). `AuthContext` resolver (4 modes in `PROVIDER_CHAIN`, the grant is the `org_members` row, `providerOrgHint` is a scope selector not authority), centralized policy evaluator (`apps/api/src/auth-policy.ts`), WorkOS SSO flow, and SCIM directory sync (6 tables, 3 idempotency guards, per-group role derivation). Route handlers consume `AuthContext` only and scope tenancy with `eq(<table>.orgId, auth.orgId)`.
- **MCP** → [`docs/architecture/mcp-client.md`](docs/architecture/mcp-client.md). `mcp_tool` client (3 transports `stdio`/`sse`/`http`, all SSRF-gated; `executeMcpTool` never-throws envelope; two-flag write consent; opt-in LLM exposure + Pass-2 promotion; stdio sandbox), the stdio MCP server (`packages/mcp-server`, thin proxy over the HTTP API — a read-only inspect/AI surface always advertised plus a gated write/operate surface: author/run/resume/cancel workflows, dead-letter replay by `deadLetterId`, rollback, and outbound-connection management, all behind `guardMcpWrite`), and MCP write consent (`JANUSLY_MCP_WRITES_ENABLED` + `org_configs.mcp.writeConsent`, chokepoint `apps/api/src/mcp-consent.ts` — `guardMcpWrite(auth, actionKey)` is the per-route gate).
- **AI pipeline** → [`docs/architecture/ai-pipeline.md`](docs/architecture/ai-pipeline.md). Every AI surface routes through the provider-neutral `LlmClient` (`packages/ai/src/llm-client.ts`); **supported completion posture is Anthropic-only** (`anthropic/claude-haiku-4-5-20251001`) until explicit new direction. `free_json` is the default generation mode (legacy `constrained`), plus Best-of-N, few-shot exemplars, two-pass `noop` promotion, prompt caching, cost governance (`checkBudget`/`gateBudget`), experiment harness, AI evidence side-channel, PromptOps registry, and bounded organization/workflow `janusly.md` operator guidance (scrubbed + DATA-framed; never a policy override or secret store). **Never break the AI-fallback contract**: every path degrades to `{ mode: "fallback", aiError, … }` and wraps the SDK call in try/catch.
- **Recovery** → [`docs/architecture/recovery.md`](docs/architecture/recovery.md). Recovery circuit breaker (pure decision layer + CAS pause on a consecutive-failure streak, sandbox replays excluded, audited trip, deliberately manual `POST /workflows/:id/resume`; the pause gates EVERY run entry point — `/start`, trigger ingest, scheduler — with inbound trigger events parked as `buffered` + 202 and backfilled oldest-first on resume, while cron ticks are dropped), DLQ (`dead_letters`, stable `/v1/dlq` + `/v1/dlq/clusters`, exact-identity `POST /v1/dlq/replay`, server-side filtered legacy `/dlq` + keyset `/dlq/queue` + `/dlq/counts`), bounded measured Recovery Drill outcomes + per-org validation dossier/exports, pre-enqueue causal replay claims (`dead_letters.replayClaimedAt`), generation-bound terminal impact (`run_nodes` claim token → CAS completion → idempotent `recovery_impact_events` + O(1) `recovery_impact_rollups` + atomic incident/playbook attribution; replay initiation is never a recovered win), atomic ordinary-runtime terminal failure, AI patch surface (`/ai/patch-workflow`, per-type config + structural envelopes + 0–2 scrubbed considered alternatives kept separate from deterministic evidence), sandbox replay gate (`replayMode="validation"`, the dry-run skip for write-side nodes/tools), evidence-gated Recovery Playbooks (manual draft/activate/retire, exact workflow+signature match, fresh sandbox every use, regression auto-retire), recovery feedback loop + confidence calibration, ownership workflow + incident handoff, alerting, metrics/value dashboard (set-once first-action latency + impact-bound seven-day recurrence), failure clustering, run-explain + evidence exports.
- **Scheduler & crons** → [`docs/architecture/scheduler-and-crons.md`](docs/architecture/scheduler-and-crons.md). The `schedule` node (BullMQ `upsertJobScheduler`, `schedule_entries`, `syncWorkflowSchedules`), CAS-safe delayed approval/timer jobs plus their overdue-checkpoint reconciler, the durable Postgres→BullMQ node-publication and terminal child→parent outboxes/reconcilers, and all global `system:`-prefixed crons: retention sweeps, consent-revocation memory purge, stalled-node reaper, supervised auto-healing, cron-observability heatmap.
- **Integrations** → [`docs/architecture/integrations.md`](docs/architecture/integrations.md). The integration-tools chokepoint (`packages/engine/src/integration-tools.ts` — credential resolution, `fetchHttpTarget` only / no vendor SDKs, rate-limit, usage events, `writeSide`, never-throw envelope), bounded buffered-HTTP JSON projection + template trust policy, `pdf.generate` + object store, `email.send` mailer, upstream-health awareness (fail-open), event-driven trigger nodes.
- **Web frontend** → [`docs/architecture/web-frontend.md`](docs/architecture/web-frontend.md). Canvas/layout visibility (`CANVAS_TABS`, code-split `@xyflow/react`, viewport persistence), the web deps allowlist (no shadcn/radix; hand-written CSS), i18n chokepoint (`apps/web/src/i18n/`), Recovery Center home tab.
- **Platform services** → [`docs/architecture/platform-services.md`](docs/architecture/platform-services.md). Live run streaming (SSE over Redis pub/sub; `publishRunEvent` → API hub; web uses `fetch`+`ReadableStream`, never `EventSource`), stable bounded `agent.reasoning` operational summaries (not hidden chain-of-thought), workflow health rollup + SLO policy, workflow snippets library, solution packs, onboarding ("first recovered run").
- **API contract** → [`docs/architecture/api-contract.md`](docs/architecture/api-contract.md). Legacy routes remain byte-compatible; `/v1` aliases resolve only for routes with explicit Zod request/response metadata, return stable success/error envelopes plus `X-Request-Id`, validate the JSON wire payload at runtime, and generate the checked-in OpenAPI 3.1 document from the side-effect-free `V1_CONTRACT_ROUTES` manifest. Run `pnpm contract:generate` then `pnpm contract:check`; never import the full route registry from build-time contract tooling.

## Operational core

- **Stack baselines:** Node.js **24 only** (`engines.node >=24 <25`; every Node CI lane runs 24), pnpm 11, TypeScript 7, React 19, Vite 8 (Rolldown), Tailwind 4 (CSS-first via `@theme` + `@tailwindcss/vite`), Vitest 4, Zod 4, Drizzle 1.0 RC, Postgres 18 baseline / 15 floor (CI `test_compat_pg15` runs the integration lanes on 15 via `JANUSLY_POSTGRES_IMAGE`; `docker-compose.yml` parametrizes the image), Redis 8, Vercel AI SDK 7 (`ai` + `@ai-sdk/anthropic` / `@ai-sdk/openai`; the standalone `openai` SDK is not a dependency).
- **Design system:** Workflow palette (Cobalt `#245BFF` + Cyan `#06B6D4` + green/amber/red status). `apps/web/src/index.css` is the ordered import-only entrypoint; tokens live in `apps/web/src/styles/foundations.css` (`@theme { --color-we-* }` + `:root` aliases). `.we-card` is the single card base and `.we-pill[data-tone]` the single pill-tone contract. `pnpm lint` enforces zero unowned CSS class selectors. No inline hex.
- **Tailwind 4 is CSS-first.** No `tailwind.config.ts` or `postcss.config.js`. The plugin runs through `@tailwindcss/vite()` in `apps/web/vite.config.ts`.
- **Vite 8 / Rolldown:** `build.rollupOptions.output.manualChunks` must be a function, not an object literal.
- **Zod 4:** `z.record(z.string(), z.unknown())` — two-arg form.
- **Auth (dev/prod gate; full resolver in the auth doc):** dev-mode uses `x-org-id` + `x-user-id` headers, auto-allowed when Supabase is unset **and** `NODE_ENV !== "production"`. Production without Supabase needs explicit `ALLOW_DEV_AUTH_HEADERS=true` or the API refuses to start. `dev-headers` falls back to the `admin` role only when no `org_members` row exists; `service-token` does **not** auto-grant admin.
- **Human form resume tokens:** `human_form` nodes pause like `approval` but resume with structured input as the node output. Waiting metadata carries an HMAC resume token (`packages/engine/src/secrets.ts`); production must set a dedicated `JANUSLY_RESUME_TOKEN_SECRET` (don't reuse `JANUSLY_API_SERVICE_TOKEN`), dev uses the local fallback. Tokens bind to org/run/node/purpose and carry a signed `issuedAt` + `expiresAt`; `org_configs.runs.humanFormResumeTtlSeconds` controls newly issued links in the closed range 300..604800 seconds (default 7 days), while already-issued links keep their signed expiry. Legacy v1 tokens without `expiresAt` retain the original fixed seven-day verifier boundary. `/resume` validates token + input (the node's JSON-schema subset) and completes only a still-`waiting` node so replays can't double-write output or double-enqueue downstream work.
- **Permission catalog + per-org custom roles:** two authz layers on `org_members.role` — rank-based `requireRole(min)` (`viewer < editor < admin`) and permission-based `requirePermission(perm)` against the closed catalog in `apps/api/src/permission-catalog.ts` (**39 keys / 19 active categories**; new key = one entry + its `defaultRoles`). Route registry fields `role?:` + `permission?:` — when both set, BOTH must pass (dispatcher runs `requireRole` then `requirePermission`). Per-org overrides + custom roles live in `org_roles` (`(orgId, name)` unique, `inheritsFrom` closed-enum, `grantedPermissions` JSONB nullable); built-ins are VIRTUAL until overridden. `getMemberRole` is custom-role-aware (non-built-in `role` → consult `org_roles` for the `inheritsFrom` rank; custom default `inheritsFrom: "viewer"`, fail-closed). Admin self-lockout guard force-includes `org.permissions.write` + `members.write` (`mandatoryAdminPermissions()`, audited in `metadata.coerced`); custom `inheritsFrom: "admin"` roles aren't coerced (e.g. a `billing-admin` with only `org.config.write`). Deleting a custom role with members → 409 `{membersAffected, code: "role_in_use"}`; DELETE on a built-in name reverts the override. `/members/invite` + `/members/role` accept custom names via `getOrgRole` fallback when `isRole` misses. Audit: `org.permissions.override_set` / `_cleared`, `org.role.created` / `_updated` / `_deleted`. (`requirePermission(perm)` maps 1:1 to CASL `ability.can(action, subject)` for a future move.)
- **Org config:** `org_configs` is only for tenant runtime settings from the closed catalog in `packages/data/src/orgConfigRepo.ts` (AI provider/model/limits, outbound HTTP bounds, safe email delivery posture, run/subworkflow policy). NEVER store secrets, tokens, API keys, DB/Redis URLs, Supabase keys, service tokens, arbitrary env vars, or workflow secret values — secret material belongs in env/vault-backed `credentials.secret_ref`. New keys must be typed (`string`/`number`/`boolean`), category-scoped (`ai`/`http`/`email`/`runs` unless the catalog intentionally grows), validated before insert/update, audited via the API, and rejected by the forbidden-name/value guards if they look like credentials.
- **HTTP/SSRF:** `ALLOW_PRIVATE_HTTP_TARGETS=false` blocks localhost/private/link-local for `http` nodes + the `http.request` tool. Validated DNS is pinned for the TCP connect via an `undici.Agent` `connect.lookup` hook, so DNS rebinding (public IP at validation, private at connect — e.g. `169.254.169.254` AWS metadata) can't redirect to a private target — don't unwind the pinned dispatcher in `packages/engine/src/http-policy.ts`. **Buffered JSON:** `http` + `http.request` preserve `body` and add `json` only for valid declared `application/json` / `application/*+json` bodies up to 64 KiB; invalid declared JSON sets `jsonParseError: true`, larger bodies set `jsonParseSkipped: "body_too_large"`, non-JSON is never guessed, and `json.parse` is the explicit read-side escape hatch. **Streaming**: the opt-in `bodyMode: "stream"` branch on `fetchHttpTarget` returns a `ReadableStream<Uint8Array>` for multi-MB CSV/PDF/image ingest (byte cap `maxResponseBytes` still aborts mid-stream, pinned `undici.Agent` still owns connect). Streams MUST be consumed in the same executor invocation — they can't survive `safePersistPayload` (substitutes a `{ __stream: true, note }` sentinel) and can't be templated via `{{...}}` (`template.ts` + `expression.ts` throw `StreamValueInTemplateError`). The `http` node + `http.request` tool auto-consume to a JSON preview via `consumeStreamToPreview(stream, previewBytes)` (cap `org_configs.http.streamPreviewBytes`, range 1024..1_048_576, default 65536, env `JANUSLY_HTTP_STREAM_PREVIEW_BYTES`); persisted output gains `{ streamed: true, streamedBytes, streamTruncated }`. Streaming previews are never JSON-projected. For CSV use the `csv.fetch` tool (`packages/engine/src/tool-registry.ts` + `csv-stream.ts`) — same streaming chokepoint, consumed row-by-row via the shared RFC 4180 `feedCsvChunk` (`csv.ts`, same `CsvParseState` that backs `csv.parse`), returning a bounded `{ totalRows, matchedRows, sampleRows, headers, streamedBytes, streamTruncated, malformedRows }` (memory `O(sampleRows × avgRowSize)` — a 50MB/1M-row CSV persists as ~50KB `state_json`). Same SSRF/DNS-pin/byte-cap/timeout/redirect guards; mid-stream byte-cap abort → `{ ok: false, streamTruncated: true, ... }` with the partial sample.
- **Template data contracts:** unresolved ordinary `context.*` / `inputs.*` paths retain the legacy empty-value behavior and emit a bounded, deduplicated `template.unresolved_path` event for that resolution phase. A persisted top-level `templatePolicy: "strict"` records the same evidence and fails before the missing value is consumed; missing or `"lenient"` stays compatible. Ordinary paths resolve before executor dispatch. Executor-owned scopes bind at their actual lifecycle point: loop `item`/`index` per iteration and sequential multi-agent `previousAgents` per completed agent (never defer `previousAgents` in parallel), with the same event/strict contract applied there. Missing `env.*` names are persisted only as `env.*`; missing `secret.*` references retain their immediate hard failure. Full-workflow AI improvement cannot invent, erase, or change this operator-owned policy.
- **Rate limiter:** API rate-limit state lives in Redis (`apps/api/src/redis.ts` + `apps/api/src/rate-limit.ts`), shared across replicas via `INCR` + `PEXPIRE` on a `janusly:rate:<name>:<orgId>` key. Fails **OPEN** with a `[rate-limit]` warn when Redis is unreachable — never fail closed; don't reintroduce the in-memory `Map` fallback. Degradation observability rides on `createRateLimiter`'s `hooks: { onRedisError, onRedisSuccess }` → `recordRateLimiterError` / `recordRateLimiterRecovery` (`packages/data/src/rate-limit-degradation.ts`; production wires the hooks in both `apps/api/src/rate-limit.ts` + `packages/engine/src/rate-limit-redis.ts`); in-memory per-process tracker, first error per `(bucket, UTC-day)` writes a `rate_limit.degraded` audit (orgId `"system"` sentinel, DB-dedup against multi-replica spam), the next success writes a one-shot `rate_limit.recovered`; trackers + the `fireHook` wrapper are try/caught so a tracker bug never breaks fail-open. Two-tier snapshot: the open `GET /health` carries a public-safe `rateLimiter` block (raw bucket/error/key withheld); the admin `GET /system/rate-limiter` exposes the full snapshot. Web `RateLimiterStatusChip` (in `OperationsPage` header) polls `/health` every 20s; copy says "Traffic still allowed" to distinguish from `BudgetBlockedBanner`.
- **Queue observability:** queue pressure uses dedicated bounded BullMQ observability connections—never the worker delivery connection on `/health` or in scrape callbacks. The API coalesces snapshots for 5s; worker count scrapes coalesce in flight and have a hard timeout. Public `GET /health` may expose only `queue: { degraded } | null`; admin `GET /system/queue` owns waiting/active/oldest/warn numbers. Oldest age begins at BullMQ eligibility, not raw creation time; previously processed work exposes unknown age because BullMQ does not retain its exact retry/stalled waiting transition. Redis failure stays `{ ok: true, queue: null }`. `JANUSLY_QUEUE_LAG_WARN_SECONDS` is server-owned (1..86400, default 60). Operations reads the admin route on its 20s infrastructure cadence; never leak live queue depth or latency publicly. The worker exports `workflow_queue_waiting_jobs` / `_active_jobs`, while API + worker each export their process-local `janusly_rate_limit_degraded_buckets`. Prometheus starts explicitly after migrations, binds to `127.0.0.1` by default (set `OTEL_METRICS_HOST` deliberately for remote scraping), fails startup on bind conflicts, uses API 9464 / worker 9465 defaults with per-process `OTEL_METRICS_PORT`, and shuts down with each process.
- **Usage events:** every LLM call writes one `usage_events` row from the chokepoint `LlmClient.generateText` (recorder registered process-globally via `setUsageRecorder(recordUsage)` at api+worker boot; `packages/ai` stays DB-agnostic). `metric: "llm.completion"`, `quantity: totalTokens`, `metadata: { provider, model, inputTokens, outputTokens, cachedInputTokens?, cacheCreationInputTokens?, latencyMs, costUsd, nodeId, mode, aiError }`; cache counts come from provider-neutral AI SDK input-token details with defensive Anthropic metadata fallback, and cost comes from `packages/ai/src/pricing.ts` (+ `JANUSLY_LLM_PRICE_<MODEL>` env override; unknown model → `costUsd: null`). Recorder failures are caught/dropped — telemetry never breaks an LLM call. Don't bypass the chokepoint by calling `aiGenerateText` directly from outside `packages/ai`. Engine `orgId` plumbs via `NodeContext.orgId` (set once per node by `executeNode` via `getRunOrgId(runId)`); every run-triggered memory recall must forward `runId` into `recallMemory` so `/run/usage` can attribute it. Operations cost/cache totals aggregate the complete rolling window in Postgres but expose at most 100 provider/model groups plus one explicit aggregate remainder row; don't replace this with an arbitrary raw-row sample or an unbounded dimensional response. The router-decision + improvement paths use `getRunMetadata(runId)` (`packages/engine/src/persistence.ts`) → `{ orgId, workflowVersionId, workflowId, createdBy, replayMode }` — don't read `orgId`/`workflowId` off the loose `RunContext` for those writes.
- **Decision engine / RL:** `packages/domain` is pure logic, no I/O; `packages/data` owns the Drizzle repos. Don't put DB queries in `domain`; don't put scoring logic in `data`.
- **Repo naming + barrel:** consumers (api + engine/worker) import the data layer from the package root `@janusly/data` (the `packages/data/src/index.ts` barrel), NOT deep `@janusly/data/src/<module>` paths — `src` is an implementation detail. The barrel flat-re-exports every public module plus a `<name>Repo` namespace per repo. No import cycle: the barrel imports repos; repos import siblings via RELATIVE paths (`./xRepo`), never the barrel. Two carve-outs stay on deep paths: the worker's lazy `await import("@janusly/data/src/<module>")` boot registrations, and test files' `vi.mock("@janusly/data/src/<module>")` targets.
- **Getter verb convention** (repo READ functions, five closed verbs): `get*` (by primary key → `T | null`), `list*` (many → `T[]`, always capped), `find*` (by non-PK criteria → `T | null`), `resolve*` (derive across multiple tables → a composed shape), `query*` (complex multi-table read → a typed envelope). WRITE verbs (`create`/`update`/`delete`/`upsert`/`record`/`set`/`revoke`/`accept`/…), DI-seam setters (`setX`), and predicates (`is*`) are a separate vocabulary the getter convention does NOT touch.
- **Cascade posture:** parent deletes are intentionally orphan-tolerant — there are NO FK constraints in Janusly because `workflow_versions.workflowId` is text (so a snapshot referencing a deleted workflow can still be inspected, replayed, rolled back). (a) **Workflow delete** (`DELETE /workflows/:id`): SOFT delete — sets `workflows.deletedAt` and unregisters every BullMQ scheduler, but KEEPS `workflow_versions` + `workflow_metadata` for restore. Every workflow read excludes `deletedAt IS NOT NULL` (the keyset list, `/workflows/latest` + `/workflows/versions`, `/start`, ownership gates, tag/folder distincts) so a soft-deleted workflow behaves as "not found". The same `workflow_not_found` 404 covers the **version-write** paths when their parent is invalid: `POST /workflows/save` (`saveWorkflowVersion` pre-check) rejects a soft-deleted parent but still creates a brand-new workflow when the id is unused; `POST /workflows/rollback` (`rollbackWorkflowToVersion` pre-check) requires an existing active parent. Neither path can silently append hidden history, and a save never resurrects a tombstone (the operator restores explicitly first). Both version writers use the shared bounded unique-violation retry policy; rollback also validates the source DAG and re-syncs schedules outside the database transaction. `POST /workflows/:id/restore` clears the tombstone + re-syncs schedules from the latest version. The soft-delete loop has a web surface: the Flows list has a per-row Delete (inline-confirm → soft delete) and a **Trash** toggle that lists soft-deleted workflows via the read-only `GET /workflows/trash` (`permission: workflows.read`, org-scoped, `deletedAt DESC`, capped 100/200, keyset-paginated on `(deletedAt, id)` via `?before=<deletedAtIso>|<id>` — the `deletedAt` analogue of the active list's `createdAt` keyset) with per-row + multi-select bulk Restore. Scheduler-entry worker reads (`getScheduleEntryById` / `listAllEnabled`) also require an active parent workflow, so a stale `schedule_entries` row cannot re-run a tombstoned workflow after a teardown blip. The original hard cascade (drop `workflow_versions` + `workflow_metadata` + the `workflows` row) is DEFERRED to the `system:retention` sweep, which purges workflows soft-deleted longer than `retention.deletedWorkflowsDays` (default 30). Orphaned `runs` / `audit_logs` / `dead_letters` rows are still tolerated (no FK). When adding a new query that returns workflows, filter `isNull(workflows.deletedAt)`. (b) **Org delete**: no cascade (workflows, runs, `memory_entries`, `audit_logs`, `mcp_connections`, `alert_policies` all remain; re-creating an org with the same id inherits prior state; no admin route exposes it — operator DB op). (c) **Member delete** (`DELETE /members`): no cascade — only the `org_members` row is removed (their session expires on the next request via the resolver returning null); their workflows / triggered runs / audit rows stay (audit is append-only). New repos default to orphan-tolerant; cascade ONLY when child rows are operationally meaningless without the parent (the `workflow_versions` case is the precedent) — document the choice in the repo's file header.
- **Audit transaction chokepoint:** `packages/data/src/audit-tx.ts:withAuditTx<T>(handler)` wraps `db.transaction(...)` so an entity insert + its `audit_logs` row commit or roll back together. The handler gets a `tx` handle + a tx-bound `audit` function; calling the module-level `audit()` inside the handler bypasses the tx (name-shadowing convention; TS can't enforce it). Used by `commitMemory` (`memory_entries` + `memory.entry.created`), the SSO callback, credential rotation (`credentialsRepo.ts` + `credentials-routes.ts`), and `orgMembersRepo.ts`. The module-level `audit()` (`apps/api/src/audit.ts`) stays the canonical non-tx chokepoint; `writeAudit` in `memoryEntriesRepo.ts` stays for legitimate post-write best-effort audits (`memory.bulk.purged`, recall failures). The MCP `createConnection + runDiscovery + audit` triplet is intentionally NOT wrapped (network I/O would hold a Postgres tx across the child-process spawn). **Typed route-audit helper:** `auditAction(auth, action, { targetType?, targetId?, metadata? })` (`apps/api/src/audit-helper.ts`) — `action` typed against the closed `AuditAction` catalog (typo = compile error); auto-derives `source` + the `actor` block (`{ userId, mode, serviceTokenSuffix }`); supersedes the old per-route `mcpAuditMetadata(auth)` spread. System-actor / skipAuth writers (`scim-event-handler`, `auto-healing-watcher`, `budget-gate`, membership-resolver, SSO callback, SCIM webhook) stay on the lower-level `audit()`. **Audit READ:** `GET /audit?action=&cursor=&limit=` (`role: "admin"`) → `queryAuditLogs` (`auditLogsRepo.ts`), org-scoped, optional `action` PREFIX filter, `(createdAt,id)` DESC keyset (cursor `<iso>|<id>` via `parseEventsCursor`), cap `AUDIT_LOG_PAGE_MAX = 200` (default `AUDIT_PAGE_SIZE`); pure `buildAuditPage`. Web `AuditLogPanel` (Operations → Access).
- **Tool registry:** entries in `packages/engine/src/tool-registry.ts` are typed `ToolDefinition`s with required `inputSchema` + `outputSchema` (Zod 4). `validateToolInput` + `executeTool` route inputs through `safeParse`; outputs are validated before return. Adding a tool without both schemas is a TS error at registration. The public `listTools()` shape (`name`, `description`, `required`, `optional`, `inputExample`) is part of the AI Studio contract — `required`/`optional` are derived from the input schema; don't drift the field names.
- **Bounded loop execution:** omitted `loop.mode` remains the legacy pure `map` contract. `mode="for_each"` runs one registered tool per item inside the SAME node (never a queue primitive), with at most 1,000 items and concurrency 1..20 (default 4). Render every per-item input before the first effect; use exactly one count-or-percentage failure budget; count throws and `{ ok:false }` envelopes as failures; keep per-item/aggregate diagnostics bounded. Reuse `tool-execution.ts` for org defaults and dry-run classification. Write-side timeouts or exceeded budgets carry `writeSide=true`, stop dequeuing new items cooperatively, and MUST NOT whole-node retry; operator-gated replay is safer than duplicate external effects. Failed-items-only redrive remains future recovery work.
- **Postgres DB query tools:** `db.schema.describe`, `db.query.read`, `db.query.write`, and `db.query.transaction` are Postgres-only and credential-scoped (`credentials.kind === "postgres"` for the current `orgId`). Workflow JSON stores the credential name only; the DSN lives in env via `credentials.secret_ref`. Tenant isolation is NOT SQL-rewrite-based — customer databases must isolate via DSN/role/schema/RLS/views. SQL validation rejects semicolons, comments, DDL/session-control verbs, verb-class mismatches, and placeholder/param mismatches. Never echo connection URLs, passwords, env-var names, or secret-shaped upstream errors. Pools/rate limits/usage are keyed by org+credential (max five external pools per org/process, one connection each; `org_configs.integrations.db.rateLimitPerMin` / `JANUSLY_DB_TOOL_RATE_LIMIT_PER_MIN`). `db.query.write` + `db.query.transaction` are write-side (validation-mode skip + readiness approval warning); schema/read tools remain read-side.
- **Vector memory tools:** `vector.search` + `vector.upsert` (`packages/engine/src/vector-tools.ts`) expose the org-scoped pgvector memory substrate to workflow `tool` nodes — thin wrappers over `recallMemory` / `commitMemory` (`packages/data/src/memoryEntriesRepo.ts`); they DON'T re-implement embedding or DB access. Tool-written vectors use the dedicated `workflow_vector` memory kind (kept apart from the recovery kinds).
