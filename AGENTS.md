# Agent Notes — Janusly

Operational invariants only. Keep planning notes, task identifiers, and release
status out of source comments and user-facing documentation.

Janusly is the AI operator for business workflows. Use **Janusly** in all
user-facing copy.

## Repository shape

- Go module: `github.com/johnny4young/janusly` at repository root.
- Runtime entry point: `cmd/api` and production executable name `janusly`.
- Backend implementation: `internal/`.
- React frontend: `web/`; it is the only pnpm project.
- OpenAPI: `contract/openapi.json`, generated by `go run ./cmd/contract`.
- Database: PostgreSQL 18 only, one fresh baseline in
  `internal/migrate/sql/00001_baseline.sql`.
- Production: one executable serves API, React assets, workers, and maintenance.

Do not add root JavaScript workspaces, separate API/worker processes, alternate
database majors, schema upgrade bridges, or runtime-name aliases.

## Commands

Use the root Makefile:

```bash
make dev
make build
make artifact
make db-up
make migrate
make generate
make lint
make test
make test-integration
make test-e2e
make verify
```

Frontend commands must run from `/web`. In nested worktrees use
`pnpm --ignore-workspace` so a parent checkout cannot capture the project.

## Runtime invariants

- `JANUSLY_ENV=production` is the only production gate.
- Public HTTP defaults to `:3001`; internal metrics default to
  `127.0.0.1:9464`.
- The serving path always mounts `internal/webdist.Handler()` after API routes.
- Production browser requests are same-origin. Vite owns the development proxy.
- PostgreSQL is the durable queue and rate-limit state store. LISTEN/NOTIFY is a
  wake-up optimization; polling remains the fallback.
- API and execution use separate bounded PostgreSQL pools.
- Every background loop is supervised and drains before pools close.
- `make db-reset` must retain its explicit `CONFIRM=reset` guard and may only
  remove volumes belonging to the configured Compose project.

## Security invariants

- Route code consumes the centralized auth context and scopes every query by
  organization.
- Production requires verified build provenance and
  `JANUSLY_RESUME_TOKEN_SECRET`.
- `ALLOW_DEV_SSO_BYPASS` is always refused in production.
- Credential values never appear in list, health, log, audit, or error payloads.
- Outbound HTTP retains SSRF validation, redirect validation, DNS pinning,
  response byte limits, and timeouts.
- Write-capable tools remain gated by static capability metadata, tenant
  consent, and validation-mode suppression.
- AI calls must preserve deterministic fallback envelopes; telemetry failures
  may not break user requests.

## Validation expectations

A change is incomplete until its relevant generated files and tests pass.
`make generate` must leave no drift. Database changes require a fresh
PostgreSQL 18 migration test and an idempotent second migration. Frontend work
requires lint, typecheck, unit/browser tests, and a production build. Runtime
or deployment work requires executable-level E2E coverage.

Do not push, merge, deploy, release, tag, or delete remote state without
explicit user authorization.
